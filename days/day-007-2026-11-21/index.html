第 7 天 · 把回答拆开用：只取正文、处理报错

2026 年 11 月 21 日 · 星期六 · 第 7 天 · 阶段 1

标准版 30–60 分钟 · 保底版 10 分钟（只做“保底任务”那一节）

今天要达到什么

做完今天，你的程序要学会一件事：大模型回的东西，不一定是你要的样子。它可能回错话（状态码不是 200）、回空话（正文是空的）、甚至根本没连上。昨天的代码遇到这些情况会直接崩——屏幕上跳出一大段红色报错，程序停了。今天把它改成：出问题也不崩，只印一句人话，告诉你哪儿不对。

还要学会两个新工具：.get()（取字典里的东西，取不到也不崩）和 try / except（先试着跑，跑坏了就接住）。这两个工具，以后 Agent 每调一次模型、每读一次文件都会用到，是 Agent 不怕出错的底气。

1 · 昨天代码的软肋：三行能崩的地方

昨天那段取回答的代码只有一行，但它默认了三件事，每件都可能不成立：

reply = data["choices"][0]["message"]["content"]

第一，data 里一定有 choices 吗？服务器一忙，回来的可能是一个报错字典，里面根本没有 choices 这一项，用 [] 取就会报 KeyError。

第二，choices 里一定有东西吗？模型可能一个候选都没给，choices 是个空列表 []，[0] 取第一项就会报 IndexError。

第三，content 一定是正文吗？它可能是空字符串 ""，也可能是 None（意思是“这里没有东西”）。程序拿着空的 content 当回答往下走，后面每一步都会错。

第 3 天学过，报错先看最后一行。但 Agent 以后一次要调几十上百次模型，靠你每次盯着最后一行救场是不行的——程序自己得学会“拿不到就认、认了就说一声、说了就继续”。

2 · 新工具一：.get()，取不到就给个默认值

字典除了能用 [] 取值，还能用 .get() 取。两者的区别只有一句：

data["choices"]        # 有就给，没有就崩（KeyError）
data.get("choices")    # 有就给，没有就给 None，不崩

.get() 还能自己定“没有时给什么”：data.get("choices", []) 的意思是“有 choices 就拿它，没有就给一个空列表”。今天代码里写的是 data.get("choices") or []，意思差不多：如果取出来是 None，就用空列表代替。

还有一个小细节：None、空字符串 ""、空列表 []，在 if 里都被当成“假”。所以 if not choices: 这一句，能同时挡住“没有 choices”和“choices 是空列表”两种情况，不用分开写两次。

为什么不用 if content is None？因为空话有两种样子：None（没有东西）和 ""（东西是空的）。if not content: 两个都挡得住，写 is None 只能挡住前一个。记住一句口诀：想判断“有没有拿到能用的东西”，用 if not x；想精确判断“是不是 None”，才用 is None。

3 · 新工具二：try / except，先试，坏了就接住

.get() 管的是“字典里有没有这一项”，还有一类问题它管不了：网络本身出问题。比如网断了、服务器超时没回，requests.post() 这一步就会直接抛异常，程序没等到回答就崩了。

try:
    r = requests.post(...)   # 先试着跑
except requests.exceptions.RequestException as e:
    print("没连上服务器：", e)
    return None              # 跑坏了就接住，印一句人话，返回 None

try 后面的代码是“先试着跑”；except 后面的代码是“跑坏了怎么办”。requests.exceptions.RequestException 是个大筐，超时、断网、连不上都装在里面，写它一个就够了，不用每种错单写一个。

同样的办法也用在 r.json() 上：服务器偶尔回的不是 json（比如一段报错网页），r.json() 会报 ValueError，接住它，印一句“回的不是 json”，再把原文印出来给你看。

return None 是什么意思？None 就是 Python 里“没有东西”的意思。今天的规矩是：函数拿不到正文，就回一个 None，调用它的人看到 None 就知道“这次没拿到”，而不是拿到一半报错。这样主程序最后只要判断一次 if reply is None，就能分清“拿到了”和“没拿到”两种情况。

4 · 完整代码：parse_reply.py

文件已经放在今天的文件夹里了，名字叫 parse_reply.py。它就是昨天的 call_api.py 加了两层保护：取回答的活儿交给 get_reply()，发请求的活儿交给 ask()，主程序只剩三行——问、等、印。

import requests

BASE_URL = "https://api.helloltq.dpdns.org/v1"
MODEL = "deepseek-v4.1-flash-1017"


def get_reply(data):
    """从大模型回来的字典里只取正文；取不到就回 None，绝不报错。"""
    if not isinstance(data, dict):
        return None
    choices = data.get("choices") or []
    if not choices:
        return None
    first = choices[0]
    if not isinstance(first, dict):
        return None
    message = first.get("message") or {}
    content = message.get("content")
    if not isinstance(content, str):
        return None
    content = content.strip()
    if not content:
        return None
    return content


def ask(api_key, question):
    """发一句话，回来只给正文；出问题就把原因印出来，回 None。"""
    try:
        r = requests.post(
            BASE_URL + "/chat/completions",
            headers={
                "Authorization": "Bearer " + api_key,
                "Content-Type": "application/json",
            },
            json={
                "model": MODEL,
                "messages": [{"role": "user", "content": question}],
                "max_tokens": 200,
            },
            timeout=60,
        )
    except requests.exceptions.RequestException as e:
        print("没连上服务器：", e)
        return None

    print("状态码：", r.status_code)
    if r.status_code != 200:
        print("这次没调通，服务器回的是：")
        print(r.text)
        return None

    try:
        data = r.json()
    except ValueError:
        print("服务器回的不是 json，没法拆：")
        print(r.text)
        return None

    return get_reply(data)


api_key = input("把你的令牌粘贴进来（粘贴后按回车，不会显示在文件里）：").strip()
question = input("想问大模型什么？直接打一句话：").strip()

reply = ask(api_key, question)
if reply is None:
    print("这次没拿到正文，上面已经印了原因，改好再跑一次就行。")
else:
    print("大模型回你：")
    print(reply)

新东西只有一个：isinstance(data, dict) 就是问一句“data 是不是字典？”——是就继续拆，不是就直接回 None。它和 type() 不一样的地方以后再说，今天只记住它是用来“先验货、再动手”的。

5 · 一行一行读懂它

get_reply() 是层层设卡：每一层先问“这东西在不在、是不是我要的样子”，不在就立刻回 None，不往下走。data 不是字典 → None；choices 没有或为空 → None；第一项不是字典 → None；content 不是字符串、或是空的 → None。只有一路都通过，才把正文交出去。最后那个 .strip() 是把正文前后多余的空格和换行去掉，回答看起来更干净。

ask() 是把“发请求”和“拆回答”分开：发请求那一段只管“连没连上、状态码对不对”；r.json() 那一段只管“回来的东西能不能拆成字典”；拆字典的活儿再交给 get_reply()。哪一步出问题，哪一步自己印原因、回 None，后面的步骤就不用跑了——这就是第 2 天说的“函数把一件事包起来”，今天包的是“问一次模型”这件事。

主程序最后的 if reply is None：这是全程序唯一要你判断的地方。reply 是 None，说明上面某一层已经印过原因了，这里只补一句“改好再跑一次”；不是 None，就是拿到了正文，印出来。注意这里写的是 is None，不是 == None——判断“是不是 None”要用 is，这是 Python 的习惯写法。

令牌的规矩不变：还是老三条——不写进文件里，不截图发给别人，万一发出去了就去中转后台删掉重建。今天的代码和昨天一样，令牌只活在运行的那一刻。

6 · 动手试两种坏情况

好代码要拿坏情况试，光跑通一次不算。做下面两组对比：

第一组，正常问一次：python parse_reply.py，粘贴令牌，问一句短的，比如“用一句话介绍鲁班”。应该看到状态码 200，然后印出回答。

第二组，故意写错模型名：把文件里的 MODEL 改成一个不存在的名字，比如 "deepseek-不存在的模型"，再跑一次。服务器会回 404，程序应该印出状态码和服务器的回话，最后补一句“这次没拿到正文”，全程不出现红色报错、不崩。试完把 MODEL 改回 deepseek-v4.1-flash-1017，再跑一次确认又能正常回答了。

这两组跑完，你就亲手验证了今天的核心：同样的程序，好情况给回答，坏情况给人话，两种都不崩。

用 print() 当探照灯：想看 get_reply() 每一步卡住了哪里，在它每个 return None 之前加一句 print()，比如 print("卡在 choices 为空")，跑一次就知道是哪一层拦住了你。试完记得把这些临时的 print 删掉，或者留着也行——第 2 天的探照灯，本来就是随时插、随时拔的。

读代码小题，4 道，带答案

第 1 题

# A：data = {"choices": []}
# B：data = {"choices": [{"message": {"content": "你好"}}]}

对 A 和 B，昨天的写法 data["choices"][0]["message"]["content"] 和今天的 get_reply(data) 各会怎样？

对 B 两种写法都行，都能拿到“你好”。对 A，昨天的写法在 [0] 那里就崩了，空列表没有第一项，报 IndexError；今天的 get_reply 在 if not choices 那里就回了 None，不崩。区别就是：直接取值默认“东西一定在”，.get 加判断是先问“东西在不在”。

第 2 题

content = ""

if not content: 和 if content is None:，哪个能挡住这个空字符串？如果 content 是 None，两个判断又各会怎样？

if not content 能挡住空字符串，因为空字符串在 if 里算“假”；if content is None 挡不住，它只认 None，空字符串不是 None。如果 content 是 None，两个判断都能挡住——None 在 if 里也是“假”，同时它就是 None 本身。所以想“一把挡住所有空东西”用 if not x，想“精确只认 None”才用 is None。

第 3 题

try:
    r = requests.post(...)
    data = r.json()
except ValueError:
    print("回的不是 json")

如果网断了、连不上服务器，这段代码会怎样？except ValueError 接得住断网吗？应该怎么改？

接不住，会直接崩。断网时 requests.post() 抛的是连接异常，不是 ValueError，except 只接它写的那一种，别的照样崩。正确做法是像今天代码这样分开包：发请求那段用 except requests.exceptions.RequestException 接网络问题，r.json() 那段再用 except ValueError 接“回的不是 json”。一种错一个筐，别混在一个 try 里。

第 4 题

reply = ask(api_key, question)
if reply is None:
    print("这次没拿到正文，上面已经印了原因，改好再跑一次就行。")

为什么主程序不直接写 print(reply)，而要先判断 reply is None？如果 ask() 里不写 return None、让它直接崩掉，Agent 以后调用几十次会怎样？

因为 reply 可能是 None，直接印就只会印出一个 None，你还是不知道这次到底是拿到了空回答，还是中间哪一步出了问题。先判断，就能分开处理：拿到了就印正文，没拿到就告诉人去改。Agent 以后一次任务要调几十次模型，中间崩一次，整个任务就停了；每次都回 None 再继续，坏一次只损失一次调用，后面还能接着跑——今天这点耐心，就是以后 Agent 不怕出错的底子。

防屎山提醒

今天的屎山不在某一行代码里，在“默认一切正常”的习惯里：默认服务器一定回 200、默认字典里一定有这一项、默认列表一定不为空。Agent 的屎山就是这么攒出来的——每处默认都是一颗雷，调用次数一多，总有一颗会炸。今天的规矩就一条：凡是外面来的东西，先验货、再动手，拿不到就认、认了就说一声。这条规矩以后会出现在你每一个 Agent 里。
