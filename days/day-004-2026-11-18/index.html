2026 年 11 月 18 日 · 星期三 · 第 4 天 · 阶段 0

今天要达到什么

做完今天，你要能做到三件事：第一，用 pip 给 Python 装一个别人写好的工具包；第二，新建一个虚拟环境，激活它，在里面装东西；第三，说得清为什么每个项目都要单独一套环境，而不是全装在一起。

这一步是通向阶段 1 的门：Agent 要调大模型 API、要读写文件、要连各种服务，靠的都是别人写好的库。不会装库，后面寸步难行。今天不求装得多，只求把“装、隔离、用”这条链亲手走通一次。

1 · pip 是什么：Python 自带的“应用商店”

Python 自己只带了一部分基础功能，更多的功能在别人写好的“包”里。pip 就是帮你从网上下载、安装这些包的工具，装 Python 的时候它就一起装好了。

最常用的一条命令就是装包：

pip install requests

requests 是最常用的一个包，专门用来发网络请求——比如让程序自己去访问一个网址、把网页内容拿回来。阶段 1 调大模型 API，靠的就是它这一类包。

装完可以顺手确认一下：

pip list

pip list 会列出当前环境里装了哪些包、分别是哪个版本。刚装好的 requests 应该出现在这个列表里。

版本也可以指定：pip install requests==2.32.0 就是“只要 2.32.0 这个版本”。平时不用记版本号，装最新版就行；只有当某个教程或项目明确写了版本，才需要照着装。

还有一个国内用户几乎一定会遇到的问题：默认的下载源在国外，下载可能很慢甚至失败。加一个国内镜像源，速度马上不一样（清华源最常用）：

pip install requests -i https://pypi.tuna.tsinghua.edu.cn/simple

-i 后面就是镜像源的地址。装不上、下载一半卡住的时候，先试试加上这一段，十有八九就好了。

2 · 为什么不能全装在一起：版本会打架

如果所有包都装在同一个地方，很快会遇到一个麻烦：A 项目要 requests 的新版本，B 项目偏偏只能用旧版本——同一个包，装了新的，B 就坏了；装回旧的，A 又坏了。

这就是虚拟环境要解决的问题：给每个项目单独准备一套环境，各装各的，互不干扰。A 项目有自己的 requests 新版，B 项目有自己的旧版，谁也不碍着谁。

虚拟环境还有一个好处：项目要发给别人、或者换一台电脑接着做的时候，只要告诉对方“我这个项目用了哪些包”，对方在自己的虚拟环境里照着装一遍就能跑。环境干净，问题就少一半。

3 · 建一个虚拟环境：三步就够

Python 自带了建虚拟环境的工具 venv，不用再装别的。先 cd 进你的项目文件夹（比如今天练习用的文件夹），然后：

python -m venv .venv

这行命令的意思是：用 venv 这个模块，在当前文件夹里新建一个叫 .venv 的虚拟环境。跑完之后，文件夹里会多出一个 .venv 文件夹——那就是这个项目专属的一套 Python 环境，里面自带一份 Python 和一份 pip。

第二步是“激活”它，告诉命令行“接下来装东西、跑程序，都用这套环境”。Windows 和 macOS / Linux 的激活命令不一样：

# Windows（命令提示符 / PowerShell）：
.venv\Scripts\activate

# macOS / Linux：
source .venv/bin/activate

激活成功有一个很明显的标志：命令行最前面多了一个 (.venv)，像这样：

(.venv) C:\Users\你的名字\agent-practice>

看到 (.venv) 就说明你现在在虚拟环境里了。这时候再 pip install requests，装的东西只进这个环境，不会动你电脑上别的地方。

用完退出也很简单：

deactivate

退出后命令行前面的 (.venv) 就消失了，又回到原来的环境。

今天最容易翻车的一点：建好了虚拟环境，却忘了激活，就直接 pip install——东西装进了全局环境，白忙一场。装东西之前，先看一眼命令行前面有没有 (.venv)，没有就先激活。
.venv 文件夹不用管它：它里面是整套 Python 环境，文件很多、体积不小。以后学到 Git 会讲：这个文件夹不用提交，不用发给别人，别人拿到你的项目，自己 python -m venv .venv 建一个就行。

4 · 实战：在虚拟环境里装 requests 并跑起来

下面这串操作就是今天的标准流程，照着走一遍（完整代码也在本页同目录的 try_requests.py 里）：

python -m venv .venv
.venv\Scripts\activate
pip install requests
pip list

确认列表里有 requests 之后，跑一跑这个练习文件：

import requests

print("requests 版本：", requests.__version__)

try:
    r = requests.get("https://httpbin.org/get", timeout=10)
    print("状态码：", r.status_code)
    print("拿到数据了，长度：", len(r.text))
except Exception as e:
    print("这次没连上，报错是：", e)

requests.get(...) 就是“去访问这个网址，把结果拿回来”；r.status_code 是对方回的状态码，200 就是“成功拿到了”。try / except 在这里是兜底：网络不通的时候，程序不会直接崩掉，而是把报错打印出来给你看。

如果 httpbin.org 连不上，先别急着怀疑自己：换个能打开的网址试试，比如 https://www.baidu.com，或者检查一下 pip list 里到底有没有 requests。能跑通一次，流程就通了。

最后顺手记下这个项目用了哪些包，养成一个好习惯：

pip freeze > requirements.txt

pip freeze 会把当前环境里所有包和版本都列出来，> requirements.txt 是把这份列表存进一个叫 requirements.txt 的文件。以后在新环境里，一条 pip install -r requirements.txt 就能把这些包一次性装回来。

5 · 容易踩的四个坑

  • 忘了激活：建了 .venv 却没激活就 pip install，包装进了全局环境。装之前先看命令行前面有没有 (.venv)。
  • 激活命令抄错系统：Windows 用 .venv\Scripts\activate，macOS / Linux 用 source .venv/bin/activate，两个系统的命令不一样，抄错就激活不了。
  • python 和 python3 分不清：Windows 上一般是 python，macOS / Linux 上常常是 python3。哪个命令能跑出版本号就用哪个，不用纠结。
  • 装不上先看报错最后一行：装包失败时，报错的最后一行通常会说清原因——是网络问题、还是版本冲突。网络问题就加清华镜像源重试，见第 1 节。

测一测：读代码小题

下面四道题不用写代码，只要读，然后想一想会发生什么。点“显示答案”对一下。

第 1 题

pip install requests

这条命令把 requests 装到了哪里？是装进某个项目，还是装进整个电脑的 Python？

装进“当前正在用的那个环境”。如果命令行前面有 (.venv)，就装进这个虚拟环境；如果没有激活任何虚拟环境，就装进全局的 Python，所有项目都能看到它。所以装之前，先看自己在哪个环境里。

第 2 题

python -m venv .venv
pip install requests

建好了 .venv，但没有激活就直接装了 requests。requests 装进虚拟环境了吗？问题出在哪一步？

没有装进虚拟环境，装进全局了。建环境和激活环境是两步：python -m venv .venv 只是把环境建好，.venv\Scripts\activate（Windows）才是“开始用它”。少了激活这一步，pip 不知道你要用新环境，就装到老地方去了。

第 3 题

(.venv) C:\Users\小肥鱼\agent-practice> pip list

命令行最前面出现了 (.venv)，这说明什么？这时候 pip list 列出来的是哪里的包？

说明虚拟环境已经激活了，接下来所有的 python、pip 命令用的都是这个 .venv 里那套环境。pip list 列出来的就是这个虚拟环境里装的包，不会把全局装的那些也算进来。

第 4 题

A 项目要 requests 的新版本，B 项目只能用旧版本，都装在全局的 Python 里会怎样？用虚拟环境要怎么解决？

全局只能装一个版本：装了新的，B 就坏了；装回旧的，A 又坏了，这就是“版本打架”。用虚拟环境：给 A、B 各建一个 .venv，在 A 的环境里装新版，在 B 的环境里装旧版，各用各的，谁也不影响谁。

防屎山提醒

环境乱了比代码乱了更难收拾：全局装了一堆不知道什么时候装的包，出了问题都不知道是哪个在捣乱。从今天起养成习惯——一个项目一个虚拟环境，装东西之前先确认激活了，项目里用到的包顺手记进 requirements.txt。环境干净，代码才不容易变成屎山。
