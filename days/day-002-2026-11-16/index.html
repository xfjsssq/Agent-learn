今天要达到什么

做完今天，你要能做到三件事：第一，给 print 加上标签，一眼分清每个数字是谁；第二，在循环和函数里面插 print，看到程序每一步走到哪、每个值变成了什么；第三，凭 print 的输出，定位 bug 大概在第几行附近。

目标还是“看得懂”：你不是在学写复杂的程序，你是在学“程序不对劲时，怎么快速找到它错在哪”。以后 Agent 写出来的代码跑偏了，你就是用今天这套本事去指哪修哪的。

1 · 为什么 Agent 干活也靠 print

模型写代码也会错，而且错得越像真的越难发现。最快的定位办法，不是把几十行代码从头读到尾，而是在关键的地方打印中间结果，看哪一步开始不对。

Agent 自己干活也是这个循环：调一个工具，拿到返回结果，先看一眼返回了什么，再决定下一步。你今天练的，就是这个“先看一眼”的动作，只不过看的工具是 print。

2 · print 的三种常用写法

第一种，直接打印一个值：

count = 3
print(count)   # 显示 3

第二种，前面加个标签，说明这个数是谁——调试时最常用，因为光秃秃一个数字根本分不清：

count = 3
print("count =", count)   # 显示 count = 3

第三种，用 f 字符串把变量直接嵌进一句话里（字母 f 写在引号前面，大括号里放变量名）：

count = 3
print(f"第 1 次，count = {count}")   # 显示 第 1 次，count = 3

三点注意：

  • print("a", 1 + 2)：逗号隔开的几样东西会依次显示，中间自动空一格，结果是 a 3。
  • 标签要写清楚变量名，比如 "total ="，别只写 "结果："——两个结果一多，又分不清了。
  • print 只能帮你“看”，改不了程序的逻辑。看到错的地方，还是要回去改代码。

3 · 先补两个结构：列表和函数

第 1 天预告过，今天把 Python 最常用的两个结构补齐，只补到“能读懂”的程度。

列表（list）：一串排好队的数据，用方括号装起来：

scores = [78, 92, 85]
print(scores[0])   # 显示 78，编号从 0 开始
print(len(scores)) # 显示 3，len 就是“有几个”

for s in scores:
    print(s)       # 依次显示 78、92、85

字典（dict）：一对一对的数据，用大括号装起来，前面是名字、后面是值：

student = {"name": "小肥鱼", "score": 92}
print(student["score"])   # 显示 92，用名字取对应的值

函数（def）：把几行代码打包起个名字，以后叫名字就能重复用。return 是“把结果交还给调用它的地方”：

def double(x):
    return x * 2

print(double(3))   # 显示 6
读代码的顺序：先看函数是干嘛的（名字 + return 那一行），再看它里面每一步。看不懂某一行时，先把它当成一个黑盒子：知道进去什么、出来什么，就够了。

4 · 实战：一个算平均分的 bug

下面这个函数要算三个分数的平均分，但结果是错的。先读一遍，想想错在哪，再往下看怎么用 print 抓住它（完整代码也在本页同目录的 debug_print.py 里，可以直接跑）。

def average(scores):
    total = 0
    for s in scores:
        total = s          # <-- 有问题的一行
    return total / len(scores)

scores = [78, 92, 85]
print("平均分是", average(scores))

跑出来的结果是 平均分是 28.333333333333332，明显不对——三个 80 多分的平均分不可能是 28 分。

问题出在 total = s 这一行：它不是“累加”，而是“每次都把 total 换成当前这一个分数”。循环跑完三轮，total 只剩最后一个分数 85，85 / 3 就是 28.33。正确的写法是 total = total + s，每一轮都把新分数加到原来的总数上。

如果光看代码没看出来，就在循环里插两个 print，看每一步的值：

def average(scores):
    total = 0
    for s in scores:
        print("这一轮 s =", s, "加之前 total =", total)
        total = total + s
        print("加之后 total =", total)
    return total / len(scores)

输出是这样的：

这一轮 s = 78 加之前 total = 0
加之后 total = 78
这一轮 s = 92 加之前 total = 78
加之后 total = 170
这一轮 s = 85 加之前 total = 170
加之后 total = 255
平均分是 85.0

这就是“探照灯”的意思：每一步的值都照出来了，哪一步开始不对，一眼就能看到。如果用错的那个版本跑，你会在第一轮就看到“加之后 total = 78”，第二轮“加之前 total”明明应该是 78 却变成了 92——错的那一行就在这两行 print 中间。

5 · 定位技巧：前后各插一个 print

不知道 bug 在哪时，不用满屏插 print，用这个办法：

  • 在你怀疑的那段代码前面插一个 print("到这里了")，后面再插一个。
  • 两个都出来了，说明这段跑完了，bug 在更后面；只出来前面那个，说明程序死在了中间这一段，范围就缩到这几行了。
  • 再把这个办法往中间推一次，范围越缩越小，直到只剩两三行。
容易错：print 插太多会刷屏，反而看不清。一次只留两三个关键位置的，找到就删掉，或者改成只在不对劲时才打印。Agent 写代码也一样：日志打得到处都是，等于没打。

6 · 和报错配合着用

第 1 天说的“报错先看最后一行”，和今天的 print 是一对：报错告诉你程序在第几行停下，print 告诉你停下之前每个值是什么。

比如程序在第 5 行报错了，第 5 行前面的 print 都出来了、后面的都没出来，那问题就在第 5 行附近——先看那一行的变量，用 print 把它们打出来，对照着报错最后一行说的原因，基本就能对上号。

测一测：读代码小题

下面四道题不用写代码，只要读，然后想一想会显示什么。点“显示答案”对一下。

第 1 题

print("a", 1 + 2)

会显示什么？逗号起什么作用？

显示 a 3。逗号隔开的几样东西会依次显示，中间自动空一格；1 + 2 先算出 3 再显示。

第 2 题

name = "小肥鱼"
print(f"你好，{name}")

会显示什么？大括号是干嘛的？

显示 你好，小肥鱼。引号前面的 f 表示这是 f 字符串，大括号里的变量会被换成它真正的值。

第 3 题

total = 0
for s in [78, 92, 85]:
    total = s
print(total)

最后显示几？为什么不是 255？

显示 85。因为 total = s 是“换成”，不是“加上”：三轮下来 total 依次变成 78、92、85，只剩最后一个。要累加得写 total = total + s，结果才是 255。

第 4 题

print("第一步到了")
x = 1 / 0
print("第二步到了")

会显示什么？“第二步到了”会出现吗？这能告诉你什么？

只显示 第一步到了，然后程序在 1 / 0 那行报错停下，“第二步到了”不会出现。这就告诉你：问题在第一步和第二步之间——前后各插一个 print，出来几个、卡在哪，范围就缩到那几行了。
