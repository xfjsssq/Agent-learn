第 3 天 · 文件读写：让程序记住东西

标准版 30–60 分钟 · 保底版 10 分钟（只做“保底任务”那一节）

今天要达到什么

做完今天，你要能做到三件事：第一，打开一个 txt 文件，把里面的字读出来；第二，往文件里写一句话，再读回来确认写进去了；第三，读一个 json 文件，改里面一个值，再存回去——文件里的值真的变了。

目标还是“看得懂 + 改得动”：你不是在学文件操作大全，你是在学 Agent 最常用的一手本事。Agent 要读配置、记笔记、存进度、把结果写下来，靠的都是今天这套东西。

1 · 为什么 Agent 必须会读写文件

前两天学的 print 只能“看”，程序一关，看到的东西就没了。文件不一样：写进去的东西，程序关了还在，下次打开还能接着用。

Agent 干活也是这个道理：它今天查到的东西，要记到文件里，明天才能接着用；你要它改的配置，改完要存回文件里，下次启动才生效。不会读写文件，Agent 就只能是个“金鱼脑”，每次从头开始。

今天只学两种文件：txt（纯文字，像记事本）和 json（长得像 Python 字典，专门用来存结构化的数据，比如名字和分数）。够用了，先别碰别的格式。

2 · 读文件：open + with，记得写 encoding

读文件固定是三步：打开、读、关掉。Python 里最常用的写法是 with open(...)，它会帮你自动关文件，不用你自己记着关：

with open("notes.txt", "r", encoding="utf-8") as f:
    text = f.read()
    print(text)

这行代码一个一个拆开看：

  • open("notes.txt", "r", ...)：打开这个文件。第二个位置的 "r" 是 read（读）的意思，只读不写。
  • encoding="utf-8"：告诉 Python 文件里是中文，用 utf-8 来解。没有这一句，中文很可能读出来是乱码——这行是写中文文件时最容易漏的。
  • as f：给打开的文件起个短名字 f，后面就用它来读。
  • f.read()：把文件里的全部内容一次读出来，变成一个字符串。
  • with：这一行最贴心——缩进里的代码跑完，它自动帮你把文件关掉，你不用再写 f.close()。
不用 with 会怎样？也可以写成 f = open(...) 再 f.read()，但你得自己记得在最后写 f.close()。小脚本跑完就退出，忘了关也没大事；但程序一直跑着、文件一直开着，后面再想写这个文件就可能被占住、写不进去。所以养成习惯：打开文件就用 with。

3 · 写文件：w 会清空，a 是往后追加

写文件和读文件是同一个 open，差别只在第二个位置那个字母：

with open("notes.txt", "w", encoding="utf-8") as f:
    f.write("第 3 天：文件读写\n")
  • "w" 是 write（写）：打开就先把文件里的旧内容全部清空，再写新的。文件原来有三行字，写完就只剩你刚写这一行了。
  • "a" 是 append（追加）：不清空，在文件末尾接着写，旧内容都留着。记日记、记日志都用它。
  • write() 不会自动换行：想换行，自己在字符串末尾加 \n。忘了加，两句话会挤在同一行。
最容易翻车的一点：想追加却用了 "w"，旧内容一下全没了，找不回来。用 "w" 之前，先问自己一句：这个文件里的旧东西，还要不要？不确定就先复制一份备份再写。

4 · 实战：学习打卡本 + 改一个分数

下面这个练习一次把读、写、json 全串起来了（完整代码也在本页同目录的 file_io.py 里，可以直接跑）。

先写一个 txt 打卡本，再读回来确认：

    f.write("第 3 天：文件读写\n")
    f.write("今天学会了 open、read、write，还有 json 的 load 和 dump。\n")

with open("notes.txt", "r", encoding="utf-8") as f:
    print(f.read())

输出是这样的：

第 3 天：文件读写
今天学会了 open、read、write，还有 json 的 load 和 dump。

再用 json 存三个人的分数。json 长得和 Python 的字典一模一样，json.dump 是“把字典存进文件”，json.load 是“把文件读成字典”：

import json

scores = {"小肥鱼": 92, "小明": 78, "小红": 85}
with open("scores.json", "w", encoding="utf-8") as f:
    json.dump(scores, f, ensure_ascii=False, indent=2)

ensure_ascii=False 是让中文直接存成中文，不写它，名字会变成 "\u5c0f\u80a5\u9c7c" 这种看不懂的编码；indent=2 是让文件排版好看一点，带缩进、能换行，不写它，所有内容会挤在一行。

改分数要走“读出来 → 改内存里的值 → 再写回去”三步，缺一步都不行：

with open("scores.json", "r", encoding="utf-8") as f:
    data = json.load(f)
print("改之前", data)   # {'小肥鱼': 92, '小明': 78, '小红': 85}

data["小明"] = 88       # 只改内存里的字典，文件还没变

with open("scores.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)   # 写回去，文件才真的变了

跑完再读一次，确认文件里的分数真的变成 88 了。完整的四步输出都在 file_io.py 里，跑一遍就能看到。

5 · 容易踩的四个坑

  • 文件不存在：读一个还没建好的文件会报错 FileNotFoundError。先写一个再读，或者先确认文件名没打错。
  • 路径是相对“你在哪里运行”，不是文件在哪里：在命令行里跑 python file_io.py，open("notes.txt") 找的是你当前所在的文件夹，不是 file_io.py 所在的文件夹。所以跑之前先 cd 到 file_io.py 那个文件夹里。
  • 用了 "w" 却想追加：旧内容被清空了，见第 3 节。想留旧内容就用 "a"。
  • 改了内存里的值，忘了写回去：data["小明"] = 88 只改了内存里的字典，文件里的分数还是 78。必须再 open 一次用 "w" 写回去，文件才真的变了。

测一测：读代码小题

下面四道题不用写代码，只要读，然后想一想会发生什么。点“显示答案”对一下。

第 1 题

f = open("notes.txt", "r", encoding="utf-8")
print(f.read())

跑完之后，这个文件关了吗？会有什么问题？

没有关——代码里没写 f.close()。小脚本跑完就退出，系统会顺手关掉，没大事；但程序一直跑着、文件一直开着，后面再想写这个文件就可能被占住、写不进去。所以打开文件就用 with，让它自动帮你关。

第 2 题

with open("notes.txt", "w", encoding="utf-8") as f:
    f.write("你好")

原来文件里有三行字，写完之后还剩几行？为什么？

只剩一行，就是刚写的“你好”。"w" 打开文件时会先把旧内容全部清空，再写新的。想留着旧内容、往后接着写，得用 "a"。

第 3 题

data = {"name": "小肥鱼", "score": 92}
json.dump(data, open("s.json", "w"), ensure_ascii=True)

打开 s.json，名字会是什么样？想让它直接显示中文，要改哪里？

名字会变成 "\u5c0f\u80a5\u9c7c" 这种转义编码——ensure_ascii=True 会把所有非 ASCII 字符都转成 \u 编码。想直接看到中文，改成 ensure_ascii=False 就行。

第 4 题

with open("scores.json", "r", encoding="utf-8") as f:
    data = json.load(f)
data["小明"] = 88
print(data)

打印出来是改过的分数，但 scores.json 文件里的分数变了吗？为什么？缺了哪一步？

文件里没变，还是 78。data["小明"] = 88 只改了读到内存里的那份字典，文件本身一点没动。缺的是“写回去”这一步：再 open 一次用 "w"，json.dump(data, f, ...) 存回去，文件才真的变了。
