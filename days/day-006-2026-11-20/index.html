第 6 天 · 亲手调通一次大模型 API

2026 年 11 月 20 日 · 星期五 · 第 6 天 · 阶段 1

标准版 30–60 分钟 · 保底版 10 分钟（只做“保底任务”那一节）

今天要达到什么

做完今天，你要能做到一件事：写一段小程序，把一句话发给大模型，再把它的回答打印出来。Agent 的第一块拼图，就是这次调用——以后 Agent 再聪明，底下干活的也是这一次调用，只是外面包了一层“想一想、再调一次”的循环。

还要弄明白四个东西分别放在哪里：API 地址（找谁）、密钥（证明你是谁）、输入（你说的话）、输出（它回的话）。这四个地方找对了，任何大模型的 API 你都能照葫芦画瓢调通。

1 · 先画一张地图：四个东西各住哪儿

调用大模型，跟去一家店里点菜差不多，四个东西缺一个都不行：

你要找的店（API 地址）  →  https://api.helloltq.dpdns.org/v1
证明你是熟客（密钥）    →  你自己中转后台的令牌，运行时粘贴
你点的菜（输入）        →  messages 里的一句话
端上来的菜（输出）      →  choices[0].message.content 里的一段话

地址用的是你自己的中转，不用再注册新账号、不用再找新密钥——你平时在客户端里用的就是这个地址和这套令牌，今天只不过换成自己写代码来调它。

先说清楚“密钥”是什么：令牌就是一把钥匙，拿着它才能用你的额度。它和密码一样重要：可以粘贴给自己的程序用，但别发给别人，别写进要上传到网上的文件里。今天的代码特意不把密钥写死在文件里，跑起来的时候现粘贴，用完就忘。

输入和输出都是 json，就是第 3 天学过的那种长得像 Python 字典的东西：输入是一个字典，里面装着模型名字和你要说的话；输出也是一个字典，回答藏在 choices 这个列表的第一项里。

2 · 完整代码：call_api.py

只用第 4 天学过的 requests，不用装新东西。文件已经放在今天的文件夹里了，名字叫 call_api.py：

import requests

BASE_URL = "https://api.helloltq.dpdns.org/v1"
MODEL = "deepseek-v4.1-flash-1017"

api_key = input("把你的令牌粘贴进来（粘贴后按回车，不会显示在文件里）：").strip()
question = input("想问大模型什么？直接打一句话：").strip()

r = requests.post(
    BASE_URL + "/chat/completions",
    headers={
        "Authorization": "Bearer " + api_key,
        "Content-Type": "application/json",
    },
    json={
        "model": MODEL,
        "messages": [{"role": "user", "content": question}],
        "max_tokens": 200,
    },
    timeout=60,
)

print("状态码：", r.status_code)
if r.status_code != 200:
    print("这次没调通，服务器回的是：")
    print(r.text)
else:
    data = r.json()
    reply = data["choices"][0]["message"]["content"]
    print("大模型回你：")
    print(reply)

先别急着跑，下一节把每一块拆开讲，知道它在干什么再跑，报错了你才知道去哪儿找。

3 · 一行一行读懂它

BASE_URL + "/chat/completions"：完整的地址就是“店门口 + 菜单”。/v1 是版本号，/chat/completions 是“聊天补全”这个服务的名字，意思就是“你发一句话，我把它补全成一段回答”。

headers 里那两行：Authorization: Bearer + 令牌 是在门口亮出钥匙，告诉服务器“我有额度，让我进”；Content-Type: application/json 是告诉服务器“我发过去的是 json 格式，你按 json 读”。

json={...} 里那三样：model 是点哪个模型——这里用的是你中转上已经验证过的 deepseek-v4.1-flash-1017；messages 是你要说的话，是一个列表，里面装着一个字典，role 是 user（说话的是你），content 就是你问的那句话；max_tokens 是“最多回多少字”，200 够回一小段话，又不会一下子烧太多额度。

data["choices"][0]["message"]["content"]：这是从输出里取回答的路，一层一层剥开：data 是整个回答字典 → choices 是里面的一个列表（一般只有一项）→ [0] 取第一项 → message 是那一项里的消息字典 → content 才是真正的回答文字。第 2 天学的字典取值、第 3 天学的 json，在这里全用上了。

用 print() 当探照灯：第 2 天的老办法在这里一样管用。看不懂服务器回了什么，就在取回答之前先 print(data)，把整个字典打出来，对照着找你要的那一层在哪儿。

4 · 跑起来：三步

第一步，打开命令行，cd 进今天的文件夹（第 5 天练过的，dir 确认 call_api.py 在里面）。第二步，python call_api.py 跑起来。第三步，它先问你要令牌——去你自己的中转后台“令牌”那里新建一个、复制过来粘贴；再问你想问什么，打一句短的，比如“用一句话介绍鲁班”，按回车。

跑通了，屏幕上会先印一个 状态码： 200，200 就是“成了”的意思，再往下就是大模型的回答。

令牌的三条规矩：第一，别写进 call_api.py 里，这个文件以后是要推到公开仓库的；第二，别截图发给别人；第三，万一不小心发出去了，去中转后台把那个令牌删掉重建一个就行，不用慌。

5 · 报错先看状态码，再看最后一行

第 3 天学过，报错先看最后一行；调 API 还要多看一眼状态码，它就写在输出的第一行：

401：钥匙不对。令牌粘贴错了、多复制了空格，或者这个令牌被删了、过期了。重新去后台复制一个再试。

404：模型名字不对。服务器上没有 MODEL 里写的这个模型。去中转后台的模型列表里看一眼，抄一个列表里有的名字换上去。

超时、连不上：先看地址抄错没有，再看自己的网络——中转地址本身平时在手机上能打开，电脑上打不开多半是网络问题，换个网络再试一次。

200 但回答是空的：看看 max_tokens 是不是设得太小了，回答还没开始就被截断了；200 这个数平时够用，第一次调通别改它。

读代码小题，4 道，带答案

第 1 题

r = requests.post(BASE_URL + "/chat/completions", json={...}, timeout=60)

这次调用里，如果把 headers 整个删掉不传，服务器最可能回什么状态码？为什么？

最可能是 401。没有 headers，请求里就没有 Authorization 那把钥匙，服务器不知道你是谁、没有额度，当然不让你进。地址、输入都对也没用，门口那一关就过不去。

第 2 题

data = r.json()
reply = data["choices"][0]["message"]["content"]

data["choices"] 是字典还是列表？[0] 在这里是什么意思？如果把 [0] 漏掉，直接写 data["choices"]["message"] 会怎样？

data["choices"] 是一个列表，里面装着回答的候选项，一般只有一项。[0] 是取列表里的第一项。漏掉它就等于拿着一个列表去问它要 message，列表没有这一项，会报错——字典才能按名字取值，列表得按位置取。

第 3 题

有人把令牌直接写进 call_api.py，写成 api_key = "sk-xxxx..."，然后把这个文件推到了公开的 GitHub 仓库里。会发生什么？正确的做法是什么？

任何人打开那个仓库都能看到这把钥匙，拿去刷你的额度。正确做法就是今天代码这样：密钥不写进文件，运行时用 input() 粘贴；万一已经发出去了，马上回中转后台把那个令牌删掉重建一个。

第 4 题

把 max_tokens 从 200 改成 2，再问“用一句话介绍鲁班”，大模型会回你什么？为什么平时调通测试只用 1–2 个 token 就够了？

只会回一两个字就被截断，比如一个“鲁”字，句子根本没说完。只测“通没通”的话，这样就够了：只要状态码是 200、能收到东西，就说明地址、密钥、输入、输出四处都对了，不用等它把整段话说完才确认，白白烧额度。
